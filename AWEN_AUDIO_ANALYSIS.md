# AWEN — анализ реального звучания (Acoustics v1)

Состояние: **анализатор реализован и подключён к Algotorial V2**. В основном каталоге AWEN 2369 записей, но нет ни одного заполненного \`audio_url\` с аудиофайлом. **Реальных песен пока не проанализировано:** \`awen-audio-features.json\` содержит \`analyzed_tracks: 0\`. Это не ошибка — значения не выдумываются.

## 1. Зачем отдельный анализ

Музыкальный жанр и редакторская метка «энергия 1–5» не заменяют анализ звучания. Теперь возможно вычислить по **локальному, разрешённому к обработке полному аудио**:
- ориентировочный темп \`tempo_bpm_estimate\` (BPM); возможна ошибка вдвое/вполовину;
- \`rms_dbfs\` — амплитудная RMS-громкость (не LUFS);
- \`dynamic_range_db\` — разброс громкости активных фреймов;
- \`spectral_centroid_hz\` — спектральная «яркость»;
- \`onset_density_hz\` — частота обнаруженных звуковых атак;
- \`zero_crossing_rate\` — пересечения нулевого уровня;
- \`energy_proxy_0_1\` — **эвристическая** комбинация плотности атак, яркости и RMS; не психоакустическая оценка настроения и не показатель Spotify Energy.

Анализ занимает время. Записи и приватные пути к файлам **не выгружаются на сайт**. В GitHub попадают только измеренные числовые характеристики, длительность и SHA-256 локального исходника.

## 2. Как запустить на собственных аудиофайлах

Требуется Python 3.10+ и аудиофайлы, которыми вы владеете либо имеете разрешение их обрабатывать.

В терминале в папке клона AWEN:

\`\`\`bash
python -m pip install -r tools/audio-requirements.txt
python tools/analyze_audio.py --audio-dir "/path/to/my/licensed/music"
\`\`\`

В папке должны находиться файлы с именами идентификаторов AWEN:

\`\`\`text
awen-1.mp3
awen-2.wav
awen-2356.flac
\`\`\`

**ВАЖНО:** каждому ID должен соответствовать именно тот же исполнитель, тот же трек и **та же версия** (ремикс/кавер), что записаны в \`awen-catalog.json\`. Неверное совпадение испортит подборки.

Или используйте файл соответствий:

\`\`\`json
{
  "awen-2356": "../authorized-audio/odesza-bloom.flac"
}
\`\`\`

\`\`\`bash
python tools/analyze_audio.py --manifest audio-mapping.json
\`\`\`

По умолчанию обновляется \`awen-audio-features.json\`. Вы можете обрабатывать небольшие партии: \`--limit 20\`. Аудио длиннее 15 минут или короче 12 секунд отклоняется; никаких «кусочных» измерений для целой песни не записывается.

### Windows

\`\`\`powershell
py -m pip install -r tools/audio-requirements.txt
py tools/analyze_audio.py --audio-dir "D:\MyMusic\AWEN"
\`\`\`

Затем проверьте JSON и отправьте **только \`awen-audio-features.json\`** в GitHub. Локальные аудиофайлы не нужно загружать в репозиторий. При новом коммите файла сайт загружает новые измерения (иногда требуется сброс кэша или обновление URL версии в \`awen-services.js\`).

## 3. Подключение к подборкам

- \`awen-services.js\` читает \`awen-audio-features.json\` **перед** расчётом Algotorial.
- Принимает только записи с \`source_type=authorized_local_file\`, \`coverage=full_track\`, \`analyzer=awen-acoustics-v1\`, длительностью ≥20 с и числовым proxy в диапазоне 0–1.
- \`awen-playlist-engine.js\` вносит **небольшую поправку**: +5 баллов, если proxy близок профилю энергетики подборки; −5 при явном несовпадении. Это не жёсткая классификация, не вывод о жанре или эмоции.
- Старый порядок, редакторские закрепления, фильтры качества и проверки конкретного релиза продолжают работать.
- **Если аудиоданных нет, весь механизм работает как раньше.** В текущем репозитории \`analyzed_tracks=0\`.

## 4. Правовые ограничения и качество

Не скачивайте аудио с Apple Music, YouTube, Spotify или иных платформ обходными способами. В частности, условия Apple iTunes Search API ограничивают использование preview-музыки промоматериалами и не разрешают её скачивать/сохранять для автономного анализа: https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/

Пользовательские локальные записи — отдельный источник с собственными разрешениями. Использовать только музыку, для обработки которой у вас есть права.

Для профессионального качества в будущем понадобятся **проверка совпадения ID, нормализация по корпусу, валидированная оценка темпа, анализ сегментов композиции и ручная оценка настроения**. Этот этап ещё не реализован и не должен считаться выполненным.

\`\`\`bash
node tests/playlist-engine.test.js
python -m unittest discover -s tests -p "test_audio_analysis.py"
\`\`\`

В тестах проверяется, что данные preview/некорректной длительности не влияют на подборку, пустой реестр не меняет состав, а подходящее авторизованное полное аудио может лишь мягко изменить рейтинг.
